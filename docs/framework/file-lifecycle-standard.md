# File Lifecycle Standard

## Purpose

Digital files evolve through stages of relevance. Lifecycle management keeps systems usable over time.

## Lifecycle model

`Inbox → Current → Reference → Archive`

## Stages

### Inbox
Files first arrive here. They have not yet been renamed, categorized, or processed.

### Current
The file is active, operational, or still requires attention.

### Reference
The file is not active but may reasonably need to be found again.

### Archive
The file is retained for history, auditability, or long-term recordkeeping.

## Processing expectations

When a file enters the system, the user should:

1. confirm whether it belongs in the system
2. rename it according to standard
3. categorize it
4. place it into an appropriate lifecycle stage
5. back it up according to policy if needed

## Benefits

Lifecycle management reduces clutter, clarifies what still matters, and supports long-term retention without drowning active work in historical noise.
